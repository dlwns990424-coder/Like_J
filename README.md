# TripJ

여행지 탐색부터 일정, 숙소, 예산 및 지출 관리까지  
여행 계획을 한 곳에서 관리할 수 있는 모바일 중심 여행 플래너 웹앱입니다.

Google Maps와 Google Places API를 활용하여 도시와 장소를 검색하고, 관심 있는 장소를 저장해 실제 여행 일정으로 구성할 수 있도록 제작했습니다.

---

## 프로젝트 소개

여행을 준비할 때 여행지 검색, 방문 장소 저장, 일정 관리, 숙소 관리, 예산 및 지출 기록 등을 각각 다른 어플로 관리해야 하는 불편함을 줄이고자 시작했습니다.

TripJ는

**여행 생성 → 장소 탐색 → 관심 장소 저장 → 일정 구성 → 숙소 관리 → 지출 관리**

까지 하나의 앱에서 관리할 수 있도록 제작했습니다.

## 주요 사용자 흐름

```text
로그인 / 회원가입
        ↓
       HOME
        ↓
    여행 만들기
        ↓
 도시 / 국가 선택
        ↓
    여행 기간 선택
        ↓
     여행 생성
        ↓
      여행 상세
        │
        ├── 여행 준비
        │    ├── 여행 메모
        │    └── 관심 장소
        │
        ├── 일정
        │    ├── DAY 선택
        │    ├── 장소 일정
        │    ├── 시간
        │    ├── 메모
        │    └── 숙소
        │
        └── 지출
             ├── 여행 예산
             ├── 일정 지출
             └── 기타 지출
```

## 프로젝트 회고

이번 프로젝트를 진행하면서 기능 구현뿐만 아니라 기획 단계에서의 기능 정의, 외부 API에 대한 사전 조사, 사용자 경험을 고려한 설계가 중요하다는 점을 경험했습니다.

### 기획 단계의 구체성 부족

개발을 시작하기 전 구현할 기능과 사용할 API, 사용자의 전체적인 이용 흐름을 충분히 구체화하지 못했습니다.

그 결과 개발 과정에서 기능과 화면 구성을 여러 차례 수정하게 되었고, 예상보다 많은 시간이 소요되었습니다.

이를 통해 개발을 시작하기 전에 핵심 기능과 사용자 흐름을 명확하게 정의하고, 이를 기준으로 개발 범위를 설정하는 과정이 중요하다는 점을 배웠습니다.

### 외부 API 사전 조사 부족

Google Maps JavaScript API와 Google Places API를 활용하면서 API에서 제공하는 데이터의 범위와 제약사항을 충분히 파악하지 않은 상태에서 개발을 시작했습니다.

구현 과정에서 예상했던 데이터를 사용할 수 없거나 원하는 방식으로 활용하기 어려운 경우가 발생했고, 이에 따라 기존 로직을 여러 차례 수정해야 했습니다.

외부 API를 사용하는 프로젝트에서는 구현을 시작하기 전에 제공되는 데이터, 사용 가능한 기능, 비용 및 제한사항 등을 충분히 확인하고 이를 바탕으로 기능을 설계해야 한다는 점을 경험했습니다.

### 사용자 경험에 대한 고려 부족

기능 구현에 집중하면서 사용자가 서비스를 처음 이용했을 때의 흐름을 충분히 고려하지 못한 부분이 있었습니다.

HOME 화면에서 다음 행동을 직관적으로 파악하기 어렵거나, Map에서 검색한 장소를 생성한 여행 계획에 추가하는 과정에서 현재 어떤 단계에 있는지 알기 어려울 수 있습니다.

또한 여행 정보 · 일정 · 지출처럼 서로 연결되는 데이터가 많은 만큼 단순히 기능을 배치하는 것이 아니라 사용자가 자연스럽게 다음 행동으로 이동할 수 있도록 화면과 기능의 흐름을 설계하는 것이 중요하다는 점을 느꼈습니다.

## 개선 방향

1. **여행지 대표 이미지 기능 개선**
   - Google API를 활용한 여행지 대표 이미지 호출 오류 수정
   - 도시 및 국가에 맞는 대표 이미지가 안정적으로 표시되도록 개선

2. **여행 제목 입력 제한**
   - 여행 계획 제목의 최대 글자 수 지정
   - 긴 제목으로 인한 UI 깨짐 방지

3. **회원가입 유효성 안내 개선**
   - 비밀번호 조건이 일치하지 않을 경우 안내 메시지 개선
   - 사용자가 입력 오류의 원인을 바로 확인할 수 있도록 수정

4. **HOME 인기 여행지 기능 개선**
   - 현재 인기 여행지 카드 선택 시 바로 여행 생성 화면으로 이동하는 방식 개선
   - 여행지에 대한 간단한 정보를 먼저 확인한 후 여행 계획을 생성할 수 있도록 변경

5. **Map의 여행 계획 연결 과정 개선**
   - 장소를 관심 장소 또는 일정에 추가할 때 생성된 여행 계획이 없는 경우 여행 생성 기능 제공
   - 현재의 단순 안내에서 바로 다음 행동으로 이어질 수 있도록 개선

6. **사용자 행동에 대한 피드백 강화**
   - 일정 추가, 관심 장소 추가, 여행 생성 등의 작업 완료 시 Toast 메시지 제공
   - 사용자가 자신의 행동이 정상적으로 처리되었는지 즉시 확인할 수 있도록 개선

7. **UI 가독성 개선**
   - 일부 화면의 작은 Font Size 조정
   - 모바일 환경에서 정보의 중요도에 따른 텍스트 크기와 간격 재조정
